dsh-workbuddy-connect · v0.6.5 · 插件实现全解析

把 WorkBuddy 桌面 App 的模型
“零配置”搬进 DeepSeek Harness

一句话：复用桌面 App 的登录态 → 经本地回环 Shim 转译为 OpenAI 方言 → 以 pi-ai Provider 注册进 DSH 的 LLM 缝隙。流式、工具调用、压缩与权限仍归 Harness 所有，插件只负责“身份 + 目录 + 转发”。

Cordis 插件框架 TypeScript ESM · Node 22+ pi-ai Provider 桥接 Loopback Shim OpenAI 兼容层 React 18 双代配置卡片 tsdown 双产物构建 国内版 + 国际版 双变体
① 总架构② 框架与宿主③ 登录复用 ④ 上游协议⑤ Shim 转发层⑥ Adapter 注册 ⑦ 目录生命周期⑧ 推理档位探测⑨ 前端双界面 ⑩ 构建与发布⑪ 核心逻辑时序

01 总体架构：一张分层图

L4 表现层DSH Web / Desktop / TUI — 模型选择器 · /model 弹窗 · 设置卡片 / 插件页 · 对话 Composer
▲ 读取目录 / 配置   │   ▼ 发起对话
L3 插件宿主层src/index.ts · apply(ctx, config) — 双 VariantRuntime 装配 · 30s 凭据轮询 · fetchCatalog 单飞 + 代际校验 · settings/webServer 路由注册
▲ getModels / resolveModel   │   ▼ Bearer(shared-secret) → 127.0.0.1 随机端口
L2 协议适配层adapter.ts (PiAiAdapter) + shim.ts (Node http) — OpenAI-completions 方言 · thinkingLevelMap 映射 · 图片预算补丁 · 错误分类映射
▲ Authorization: Bearer(真 token)   │   ▼ SSE 流回传
L1 上游层upstream.ts → copilot.tencent.com / workbuddy.ai — /v3/config 目录 · /v2/chat/completions 流式对话 · /v2/plugin/auth/token/refresh 续期 · 计费接口
▲ 只读   │   ▼ 永不写入
L0 身份层桌面 App 登录文件 + 插件自留副本($DSH_HOME) — macOS ~/Library/Application Support · Windows Local/Roaming AppData · WSL 挂载探测 · 5.6 加密信封经 Electron helper 解密

设计哲学（为什么长成这样）

  • 零配置：不做自己的 OAuth，只读 App 已登录的凭据文件；装上即用，App 内切换账号自动跟随。
  • 宿主拥有对话：流式、工具调用、上下文压缩、权限全部走 DSH 原生链路，插件只提供“模型 + 密钥解析”。
  • 故障隔离：两个变体（国内/国际）各有独立 store / catalog / shim / 路由，一边失败不影响另一边注册。
  • 降级有序：目录按 live → saved(本账号上次成功) → fallback(内置快照) 三级降级，卡片如实标注来源。
  • 诚实 UI：不知道就说不知道——促销过期后倍率显示“价格未知”而非沿用折扣价；未登录则分组直接消失而非摆出点不了的模型。

02 框架与宿主：Cordis + DSH 服务缝隙

用的框架

  • Cordis v4 — DSH 的插件容器。export const name='llm-workbuddy' + export function apply(ctx, config) 即插件入口；cordis.patch.yml 把插件插入 profile 而不改默认模型。
  • ctx.inject(['llm']) — 声明依赖模型注册表；ctx.inject(['webServer']) 挂状态/探测路由；ctx.inject(['settings']) 安装两版设置分节。
  • ctx.llm.registerAdapter(['workbuddy'|'workbuddy-ai'], adapter) — 唯一向宿主暴露模型的出口；ctx.emit('llm/adapters-updated') 通知选择器重读。
  • ctx.effect() — 注册析构（释放 adapter、关闭 shim、清心跳/定时器）。

用的技术库

  • @earendil-works/pi-ai — 构造 Provider（createProvider + openAICompletionsApi），复用其 OpenAI SDK 的流式/工具调度。
  • @deepseek-ai/dsh-llm / dsh-llm-pi-ai — PiAiAdapter 基类、重试策略、图片附件解析（resolveImageAttachmentAccess）。
  • @deepseek-ai/schemastery (z) — Config schema：authFile / authFileAI / probeConsent / useMaximumContextWindow。
  • dsh-atomic-write + dsh-home-paths — 带文件锁的原子写（0600 权限）与 $DSH_HOME 定位。
  • React 18 — 浏览器 bundle 的配置卡片（src/client/*.tsx）。

03 登录复用：只读桌面凭据 + 自留刷新副本

环节实现（auth.ts / desktop-credential-protection.ts）
桌面文件定位同目录不同名：workbuddy-desktop.info（国内）/ workbuddy-desktop-ai.info（国际）。macOS 走 Application Support；Windows 依次探 Local→Roaming AppData；WSL 经 /mnt/<盘> 映射 Windows 目录；Linux 探 XDG config/data 双家。可被 WORKBUDDY_AUTH_FILE / WORKBUDDY_AI_AUTH_FILE 或设置项覆盖。
5.6 加密凭据token 字段可能是 at-rest 信封 → 用各自 App 的 Electron 二进制解密（bundle id / 注册表名 / exe 名严格按产品区分，WORKBUDDY_ELECTRON_BIN / WORKBUDDY_AI_ELECTRON_BIN 可显式指定）。两 App 恰好同密钥只是巧合，插件不依赖。
双源取胜current() 同时读桌面文件与 $DSH_HOME/.workbuddy[-ai]-auth.json：身份优先于过期时间（桌面文件的 uid 即“当前登录人”，过期更晚的旧账号副本不得冒充）；同身份才取过期更晚者。防跨区误用：region 不符直接报 credential-region-mismatch 而非把 token 送错区。
按需刷新resolve() 在过期前 5 分钟触发单飞刷新（并发共享同一 promise），写自留副本永不写桌面文件；刷新失败但旧 token 未过期则继续用旧 token 顶住会话。
解析parseWorkBuddyAuth 兼容嵌套 {auth, account} 与扁平两种文档；expiryToMs 兼容秒/毫秒时间戳。

04 上游协议：抄官方 CLI 的“方言”（upstream.ts）

参照 Sliverkiss/workbuddy2api（Go 实现）移植。按登录 domain 划分区域：*.workbuddy.ai → global，其余/空 → cn。

接口用途与要点
GET /v3/config（产品文档）模型目录。CN 用 CLI 形 UA 取 CLI 名单（保证“列出的都能聊”）；国际版用 App 形 UA（经 app-version.ts / client-identity.ts 解析真实版本号伪装）。成员 = agents[cli].models ∩ 可用行(非disabled、正输入/输出cap)。CN 另做一次 best-effort 控制台读取合并 badge:* 促销徽章。
POST /v2/chat/completionsSSE 流式对话。请求头带 X-User-Id / X-Enterprise-Id / X-Domain / X-IDE-* / User-Agent(桌面身份)；chat 请求绝不带 refresh token。国际版自动前置一条 system 消息、probe 用更大的 max_tokens 下限（GPT-5.6 系拒绝 max_tokens:1）。
POST /v2/plugin/auth/token/refresh续期（X-Refresh-Token 只出现在这里）。返回 accessToken / refreshToken / expiresIn / domain。
计费个人：/v2/billing/meter/get-user-resource 聚合各套餐余量；国内企业（enterpriseId 非空）：get-enterprise-user-usage 读周期额度（含 limitNum=-1 无上限标记）。读不懂→抛错而不报 0（“错的零比报错更坏”）。

请求体“翻译官” prepareChatBody

  • 强制 stream:true（上游拒收非流式）。
  • developer role → system（上游报 400/11128 非法渠道，否则必死）。
  • tool_choice 对象 → 上游要的字符串形（auto/required/函数名，none 则连 tools 一并删）。
  • 错误分类 classifyUpstreamError：402/积分关键词→hard_credit；401→session_dead；429→soft_rate；5xx→server 等，供 shim 映射 HTTP 状态。

05 Shim 回环层：本机伪装一个 OpenAI 服务器（shim.ts）

为什么要多这一跳？pi-ai 只会说 OpenAI 方言，而 WorkBuddy 要 CLI 头 + 自定义错误语义。Shim 让“方言转换”与“密钥管理”收敛到一处：pi-ai 永远只看到标准 OpenAI，WorkBuddy 方言只存在于 shim→上游这一段。

  • 监听：server.listen(0,'127.0.0.1') 随机端口，只绑回环；adapter 按需 shim.baseUrl()/v1 拼 baseUrl。
  • 鉴权：进程内随机 32 字节 shared-secret；adapter 以它做 OpenAI apiKey（Authorization: Bearer），shim 用 timingSafeEqual 校验，真 token 只由 shim 经 store 取得、永不经 pi-ai 之手。
  • 加固：Host 必须回环、浏览器 Origin 必须回环、chat 必须 application/json（挡 simple-request CSRF）；路由仅 GET /healthz · GET /v1/models · POST /v1/chat/completions。
  • 转发：prepareChatBody 整形 → client.chatStream → 200 则 SSE 管道直传（中途断流补 [DONE]）；失败则按 hard_credit→402 / soft_rate→429 / session_dead→401 / server→502 转写 OpenAI error，并隐藏正文里的裸 401/403 字样以免宿主误判为 AUTH。
pi-ai ──Bearer(shared-secret)──▶ 127.0.0.1:端口/v1/chat/completions
shim: 验secret → store.resolve()取真凭据 → 整形body → 上游SSE
shim ──text/event-stream管道──▶ pi-ai ──▶ DSH 对话流

06 Adapter：把目录翻译成 DSH 模型（adapter.ts）

  • 手工组装 Profile（不用 dsh-llm-pi-ai 内部的 resolveProfiles，因其非公开导出）：createProvider({id, name, auth, models, api: openAICompletionsApi()}) + ResolvedPiAiProviderProfile（含 streamIdleTimeout 5min、图片预算、空 modelErrors）。
  • 活目录：Provider 的 getModels 每次都重读 catalog.current() 并重拼 baseUrl（shim 端口是临时的）；invalidate() 重建 snapshot 并 emit('llm/adapters-updated')。
  • pi-ai 认证面钝化（INERT_AUTH）：read/list/env/fileExists 全部答“无”，modify 直接抛错——此路由没有 pi-ai 凭据生命周期，防止环境变量凭空造出凭据。
  • 推理档位映射 reasoningFields()：上游声明 supportedEfforts 非空则精确提供；否则仅当本地探测结论为 validating 时提供探测到的档位；non-validating（如 glm-5.2 照单全收）一律不给控件；off 仅当声明 canDisableThinking 才给。措辞只承诺“上游接受该拼写”，不承诺改变效果/速度/计费。
  • 显示层：WorkBuddyPiAiAdapter.listModels/resolveModel 在名字后拼 · x0.79 · 限时免费（中点分隔避免与 GLM-5.3-Flash 的连字符混淆）；只改名不改 id，路由永远按 model.id 走。
  • 显隐：隐藏只是 listModels 过滤，resolveModel 不过滤——正在用被隐藏模型的旧会话不受影响。
  • 跨代图片补丁 withLegacyImageBudget：0.1.5 附件服务要 maxPixels 而 0.1.6 给的是 {width,height,maxBytes}，Proxy 自动补像素预算，新老宿主都不断图。
  • 刻意缺席：不注册 registerConfigurableProviders ——“设置→模型”页两代都不显示 WorkBuddy 行（该页编辑器无字段可配），模型选择器与 /model 走 adapter 不受影响。

07 目录生命周期：凭据驱动 + 代际保护（index.ts）

  • 启动即隐藏：catalog.setVisible(false) ——无凭据的变体目录为空，DSH 自动藏起整个分组（而不是摆出选了必报错的兜底表）。
  • 30s 轮询 syncAll/syncVariant（纯本地文件读、零网络）：无→有则 adoptIdentity 揭示分组并拉目录；有→无则隐藏并丢弃该账号缓存；同身份成功后不再重拉；失败则按 10 倍轮询间隔退避重试。
  • adoptIdentity 四态统一：登录/登出/切换/手动刷新走同一函数——先服务本账号的 saved 目录（秒开），再异步换 live；代际计数 catalogGeneration+1 并 abort 旧请求。
  • fetchCatalog 三原则：单飞（同身份同代际共用一个 promise）；代际校验写回（慢回包若代际已变直接丢弃，杜绝 A 账号回包覆盖 B）；用 resolve() 而非 current()（过期 token 先续再拉，否则每次都失败）。
  • 三级降级：live（刚拉到）→ saved（本账号上次成功，$DSH_HOME 各变体独立文件）→ fallback（编译进包的快照，国内外各一份）；状态卡展示 source / fetchedAt / appVersion / error。
  • 按账号隔离：探测结论、显隐偏好、saved 目录全部按 uid:enterpriseId 分桶；无 uid 账号不存偏好（宁缺毋错，不串号）。
// 目录状态机（每变体独立）
signed-out: visible=false, models=[]            // 分组消失
   │ adoptIdentity(id) → 先 saved/fallback, visible=true
   ▼
fetching: inflightFetch{identity,generation}  // 单飞
   │ success → live + 持久化 saved(id) + invalidate()
   │ fail    → 保留 saved/fallback + catalogError + invalidate()
   ▼
picker: llm/adapters-updated → 选择器重读 listModels()

08 推理档位探测：用户授权、逐档实测（probe*.ts）

背景：档位信息散落在上游私有 UI 逻辑里，且有的模型“接受未知值但静默回退默认”，一次成功不能证明档位真可用。所以未声明档位的模型默认无档位控件，由用户逐模型手动探测。

  • 候选：reasoning.supports && supportedEfforts 为空 的模型；已有结论的不从列表消失（方便上游变更后重测）。
  • 方法：对 low/medium/high/xhigh/max 逐个发最小真实流式请求（reasoning_effort=候选值，读到首个 data: 即挂断，不组装答案），另发一条不带该参数的基线。先确认“上游会校验该参数”（基线 vs 候选行为差），再确认每个规范档位是否被接受。
  • 结论：validating（校验型，可授档位）/ non-validating（照单全收，不授控件），按账号持久化（.workbuddy[-ai]-probe.json，带插件版本与 TTL，目录行变更/过期/上游后声明档位则自动让位）。
  • 代价明示：探测发真实请求可能扣积分，需逐模型点确认；TUI 无探测入口（仅 Web/Desktop 卡片 + composer 右侧控件）。

09 浏览器半：一个 bundle 通吃两代 DSH（src/client/）

点实现
双缝隙自适应同时注册 settings.plugin.item（0.1.5 设置→插件，按 namespace 分发，一变体一卡）与 plugins.bundle.config（0.1.6+ 插件页，按包名分发，一页双卡）。靠 slot 声明寿命自然生效，无版本 if——宿主有什么缝，哪个回调就触发。
卡片内容WorkBuddyPluginCard 三标签：状态（账号/有效期/积分/目录来源/档位探测）· 上下文（各模型窗口 + 显隐勾选 + 国际版最大窗口开关）· 明细（套餐余量/模型优惠）。经同源 status/probe 路由取数（status-paths.ts 是 Node/浏览器共享的唯一路径源）。
Composer 控件conversation.input.right 槽位挂 WorkBuddyProbeControl，按当前会话目录判断是否可测。
升级提醒shell.overlay + update-store.ts（7 天 localStorage 缓存查 npm 新版），有缝才显。
容错guardClientContribution 双层 try/catch（注册时 + 回调触发时）：单个贡献失败只 console.error，不掀“Failed to load plugins”红幅，其他卡片与宿主模型通道照常工作。
国际化locales.ts 中英双语经 locale.register('settings.workbuddy') 注册。

10 构建与发布：tsdown 双产物（tsdown.config.ts）

产物 A · Node 宿主（ESM）

  • 入口 src/index.ts + src/bin.ts → lib/，platform:node / target:es2024 / dts:true。
  • 宿主提供的包全部 neverBundle（cordis、dsh-llm 系、pi-ai、schemastery…），避免与宿主双实例。
  • bin: dsh-workbuddy-connect 提供 status / doctor / logout --provider workbuddy[-ai] [--json] 诊断。

产物 B · 浏览器（CJS 包裹）

  • 入口 src/client/index.tsx → lib/client.js，platform:browser，externals 仅 react / cordis / slots / locale（DSH import 皆 type-only，构建后只剩 React）。
  • banner/footer 包成 window.__ModuleLoader__.load({id, factory})，宿主按需加载。
  • 版本注入：读 package.json version → define __DSH_WORKBUDDY_VERSION__，供宿主半与浏览器半共用（升级提醒比对用）。
  • 类型检查：tsconfig.json（宿主）+ tsconfig.client.json（浏览器） 双工程；vitest 覆盖上游解析/适配/客户端降级；心跳文件（host-heartbeat.ts，PID 存活判定）让 CLI 无浏览器也能报宿主健康。

11 核心逻辑时序：发一句话经历了什么

用户在 DSH 选择 [WorkBuddy · GLM-5.3 · high] 并发送 │ ├─ ① DSH 经 PiAiAdapter.resolveModel 确认模型 + thinkingLevelMap(high→'high') ├─ ② pi-ai openAICompletionsApi 组 OpenAI body → POST 127.0.0.1:随机端口/v1/chat/completions │ Authorization: Bearer <shim shared-secret>（真 token 不在此处） ├─ ③ shim: 验 Host/Origin/secret → store.resolve()（过期则先refresh续期并落盘） │ → prepareChatBody(强制stream/改developer/压平tool_choice) │ → 上游 /v2/chat/completions（带 X-User-Id 等 CLI 头 + 真 Bearer） ├─ ④ 上游 SSE → shim 管道直传 → pi-ai 解析 → DSH 渲染流式增量 └─ ⑤ 失败时按 kind 转 OpenAI error (402/429/401/502/400) → DSH 按 AUTH/计费/限流分别展示

＋ 重点速览

  • 🔌 本质是一个“身份借用 + 方言翻译”插件：不自建账号体系，不自研推理通道。
  • 🧬 双变体数据驱动：加第三个区域产品只需加一条 WorkBuddyVariant 描述，无需改分支。
  • 🛡️ 安全边界清晰：真 token 只活在 Node 侧 store→shim→上游；浏览器侧只有状态展示；回环口令防 DNS-rebinding。
  • 🔄 并发正确性：单飞刷新、单飞目录、代际丢弃、锁文件原子写，应对“App 内切换账号时 DSH 正在发请求”。
